# RAG evaluation results - Ragas and calibrated LLM judges

*Run on a single NVIDIA GB10 (DGX Spark), 2026-11-02. Generator and main judge: Gemma 4 26B-A4B (llama.cpp, shared with other jobs, <=2 concurrent requests, thinking off).
Second judge: Qwen3-4B-Instruct-2507 on a dedicated vLLM server. Ragas 0.4.3.
Every number below is produced by a script in this repository; the curated raw outputs (judge verdicts, answers without passage text, calibration reports) are in `results/rageval/`
and re-score to exactly the reports quoted here (`tests/rageval/test_committed_results.py`). Commands: [REPRODUCING.md](REPRODUCING.md).
Concepts and interview questions: [EXPLAINER.md](EXPLAINER.md).*

## 0. Headline numbers (read this first)

1. **Baseline RAG (dense top-3 + Gemma, XQuAD ar/en, 180 questions):** gold passage retrieved for 81% of answerable questions; 21% of answerable questions were refused (28 of the 34 refusals were retrieval misses); 20/20 unanswerable questions correctly refused; **27% of the real answers were in the wrong language** (every one to an English question) - a defect no Ragas metric detects. End-to-end *acceptable-answer rate* 59.4% [52.2, 66.7].
2. **Improvement (rerank top-10 -> top-3 + explicit output-language instruction):** acceptable-answer rate **59.4% -> 85.0%** (+25.6 points, CI [+18.3, +32.8], McNemar 51 fixed / 5 broken; confirmed on 48 fresh questions: 58.3% -> 85.4%, +27.1 [+14.6, +39.6], 13 fixed / 0 broken). Of that, the language instruction accounts for +26.8 points of right-language answers, reranking for +10.6 points of gold-hit@3 and -10.0 points of over-refusal. Pure content correctness improved only +6.7 points [+1.1, +12.2] (p = 0.02, would not survive a Bonferroni correction; +6.2 [0.0, +14.6] on the fresh set - underpowered). Chunking did not help (hit@3 0.831 vs 0.812).
3. **Judge calibration against 180 planted errors (test split, n = 91; kappa vs ground truth):** Qwen3-4B one-shot end-to-end judge **0.42** -> decomposed pipeline **0.97**; Gemma one-shot **0.95** -> pipeline **1.00** (difference CI [0.00, +0.12]); correctness judge Gemma naive 0.87 -> rubric 1.00; faithfulness Gemma naive 0.81 -> sentence-split verifier 1.00. A string-match baseline reaches 0.96 on correctness (the set favours it). **The set saturates: it cannot rank strong judges.**
4. **What judges miss:** the naive Qwen judge catches 11% of invented sentences, 0% of omitted facts, 0% of wrong-language answers, 19% of wrong citations; an LLM claim-extractor (Ragas-style `faith_v2`) catches only 33% of invented sentences because it drops them, while the same verifier on a deterministic sentence split catches 100%. Wrong numbers - including x10, off-by-one and Arabic-Indic-digit versions - are caught by every competent judge with 0% false positives on correct re-scripted numbers; weak prompts leak (Gemma `correct_v0` misses 27% of near-miss numbers). Gains came largely from deterministic checks (language, abstention): LLM parts alone reach recall 0.89-0.95.
5. **Ragas (Gemma evaluator; 20 stratified questions + 6 targeted retrieval misses):** works mechanically (0 parse failures / metric errors in 469 calls) and its context recall / precision *do* react to real retrieval misses (1.00 / 0.90 when the gold passage was retrieved vs 0.29 / 0.29 when it was not). It misbehaves on: correct refusals (answer relevancy forced to 0), bare-span references (FactualCorrectness 0.10 vs 0.53 with sentence references), wrong-language answers (undetected), and as a pass/fail classifier on planted errors (Qwen evaluator: FactualCorrectness kappa 0.42-0.55, faithfulness flags 100% of correct refusals).
6. **Judge biases (pairwise):** Qwen3-4B has strong position bias on ties (slot A 92%, order-consistent 17%) but none on clear-cut pairs; Gemma has none but prefers concise answers and ASCII-digit answers 100% of the time in forced choice; self-preference not detectable (both prefer Qwen-written answers; style confound).
7. **Judge-vs-judge:** Gemma vs Qwen agree well on narrow rubric tasks (pipeline 0.97, faithfulness 0.93, correctness 0.85 kappa) and poorly on one-shot prompts (0.34-0.45); on 268 *real* answers their correctness agreement is only kappa 0.48 (raw 91%) - Qwen is stricter; Gemma was right in the 5 disagreements we read.
8. **Human hook:** `runs/rageval/human_labeling.csv` (40 items, blank labels, generated by `export_human.py`) + `agreement.py`; tested on synthetic labels only.

## 1. What was built

**Data (XQuAD, Artetxe et al. 2020; CC BY-SA 4.0 - underlying SQuAD v1.1 text is CC BY-SA 4.0 Wikipedia).** XQuAD is the 240 SQuAD-v1.1 dev paragraphs
professionally translated into Arabic, so every paragraph/question exists in both languages with the same ids. We exploit that:

| piece | size | how |
|---|---|---|
| corpus | 220 passages (110 English, 110 Arabic) | each of 240 paragraphs goes in ONE language at random; 20 paragraphs held out |
| answerable eval questions | 160 | 40 each of ar->ar, ar->en-passage, en->en, en->ar-passage (cross-lingual cases are 50%) |
| unanswerable eval questions | 20 (10 en, 10 ar) | the question's paragraph is removed from the corpus (both languages); its Wikipedia-article neighbours stay, so retrieval returns topically close but non-answering passages; answer string verified absent from every corpus passage |
| question pool for judge calibration | 932 other XQuAD questions on corpus paragraphs | never used to score the RAG system, so judge tuning cannot leak into the headline numbers |

Reference answers are the XQuAD answer spans (short: "308", "Bilateria"); for Ragas, where bare spans break reference-based metrics
(section 3), references are expanded to the human-translated sentence containing the span.

**RAG system.** `retrieval.py`: embed with paraphrase-multilingual-MiniLM-L12-v2 (384-d) -> exact cosine top-k over a 220-passage index (`rag_eval_xquad`, `rag_eval_xquad_chunks`) -> optional cross-encoder rerank
(mmarco-mMiniLMv2-L12-H384-v1) -> Gemma with a grounded prompt that must cite `[P012]`-style ids and answer "Not in the documents." when unsupported.
*Why this stack:* it is a production-shaped system (embedder, vector search, cross-encoder, citing generator) and it has a known weakness worth finding (128 word-piece embedder truncation).
*Retrieval backend, an honest note:* the published runs queried a self-hosted HTTP embed/rerank service and a Qdrant collection serving exactly these two models. That service was scaled down (by someone else) at ~21:12 on the run day, so
retrieval fell back to in-process copies of the same two models for everything after that (verified: locally computed vectors match the stored Qdrant vectors with cosine 1.000 for the passages checked).
This repository ships the in-process path only: `retrieval.py` keeps the same `create_collection / upsert / search / retrieve` API over an on-disk exact-cosine index, so no service is needed.

## 3. Ragas evaluation of the baseline (Gemma as evaluator LLM)

**Setup.** Ragas 0.4.3 (`ragas.metrics.collections`): `Faithfulness`, `AnswerRelevancy` (embedder = BAAI/bge-m3, and, on the *same* generated questions via the LLM cache, the RAG system's own
multilingual MiniLM, so the difference isolates the embedder), `ContextPrecision` (with reference), `ContextRecall`, `FactualCorrectness` (F1) plus a bge-m3 cosine "semantic similarity"; Gemma 4 26B-A4B, temperature 0
(0.4 for the 3 samples of answer relevancy), grammar-constrained JSON. 469 LLM calls, **0 structured-output parse failures, 0 metric errors**.
**Scope (honest):** Gemma took 3-8 calls/min under shared load, so Ragas ran on a stratified sample - 4 questions in each of the 4 (question language x evidence language) cells = 16 answerable + 4 unanswerable - plus 6 extra answerable questions whose gold passage was *not* retrieved (to see whether Ragas notices retrieval failures). Per-cell n = 4 and per-language n = 8: **these are descriptions with wide intervals, not benchmarks.**

**Toy sanity check first** (`python -m arretrieval.rageval.toy_ragas`, expected values derived by hand): faithfulness of a fully supported answer 1.0 (got 1.0) and of an answer with 1 of 2 claims invented 0.5 (got 0.5); context recall with 1 of 2 reference facts in the context 0.5 (0.5), with both 1.0 (1.0);
context precision with the useful chunk first 1.0 (1.0), second 0.5 (0.5); factual correctness identical answer 1.0 (1.0), wrong number (380 vs 308) 0.0 (0.0), Arabic version 1.0 (1.0) and **with Arabic-Indic digits ٣٠٨ vs 308: 1.0** (digit script is handled);
**but a correct answer scored against the bare reference "308" got 0.0** - see below.

### 3.3 What misbehaved, and why

| observation | evidence | why |
|---|---|---|
| **A correct refusal is scored as a failure.** Answer relevancy = 0.00 for every refusal (4 correct abstentions + 6 refusals caused by a retrieval miss); faithfulness of a correct refusal is 0.75 (one of four scored 0). | 3.1 `unanswerable` row | Ragas flags "noncommittal" answers and multiplies relevancy by 0; the claim extractor has nothing to extract from "Not in the documents" and the verifier may call it unsupported. Abstention needs its own metric (we use abstain-iff-unanswerable). |
| **Bare-span references break reference-based metrics.** FactualCorrectness = 0.10 against XQuAD's span reference vs 0.53 against the reference expanded to its sentence (n = 16); toy: a correct answer vs "308" = 0.0. | `factual correctness span ref` column; `toy_ragas.py` | The reference decomposes into zero or one trivial claim, so NLI recall/precision degenerate. Datasets with short-span answers (SQuAD-style, TyDi, many internal FAQ sets) need sentence-level reference answers before Ragas correctness means anything. |
| **Even with sentence references, FactualCorrectness is a weak correctness signal.** Mean 0.59 when the reference string *is* in the answer vs 0.40 when it is not (n = 11 / 5); F1 is capped by recall against a reference sentence that contains more facts than the question asked; on the 96-item planted set the (Qwen-evaluated) metric only separated the extreme scores (dev-tuned threshold tau = 0.10, kappa 0.42-0.55, catching 20-38% of wrong numbers). | 3.1; section 4.3 | Claim-level F1 mixes "answered the question" with "restated everything in the reference". |
| **Context recall / precision DO track real retrieval failures here.** Gold retrieved: recall 1.00 / precision 0.90 (n = 15); gold not retrieved: recall 0.29 / precision 0.29 (n = 7). | 3.2 | A genuine strength: these metrics are LLM-judged but anchored to the reference, so they react to missing evidence. (With n = 7, treat 0.29 as "much lower", not as an estimate.) |
| **Answer relevancy is nearly blind to the answer's language and to the embedder.** bge-m3 0.76 vs MiniLM 0.74 on the same generated questions; wrong-language answers 0.75 vs right-language 0.77 (n = 4 / 12). | 3.1, diagnostics | Plausibly: the metric measures topical similarity of regenerated questions, and a multilingual embedder maps an Arabic answer's regenerated question next to the English original. |
| **Faithfulness is lower (0.81 vs 1.00) for wrong-language answers** (n = 4 / 12; English questions over Arabic passages). | diagnostics | Plausibly an artefact of cross-lingual claim verification (statements in one language checked against context in another); with n = 4 only a hypothesis, but it matches the planted-set finding that Ragas faithfulness (Qwen evaluator) false-alarms on 17-38% of correct items that merely re-script a number. |
| **Nothing in Ragas flags the 27% wrong-language answers or checks citations.** | section 2.2 | No metric inspects output language or `[P012]` ids; a deterministic check does it in 5 lines. |
| **Arabic is not systematically penalised by the pipeline itself** (Arabic questions: faithfulness 1.00, relevancy 0.77 vs English 0.91 / 0.76), the weaker cells are cross-lingual ones (English question over Arabic passage: FC 0.30, similarity 0.62). | 3.1 | Cross-lingual reference/answer pairs are harder for claim-level NLI and for embedding similarity; n = 4 per cell. |

## 4. Judge calibration against planted errors (the core experiment)

never straddle the split; "dev" is where prompts were written/inspected, "test" is where we report). Labels are true **by construction** - no annotator:

Class balance: 46 acceptable / 134 defective (test split: 27 acceptable / 64 defective; per-type test counts are only 4-15, which is why the per-type matrix in 4.5 uses all items). All numbers below treat **DEFECT as the positive class** (so "recall" = fraction of defects caught, "precision" = fraction of
flagged items that really were defective). Each judge is scored on the axis it is asked about: faithfulness judges vs `faithful`; correctness judges vs `correct`;
`cite_v1` vs `attributed` (= faithful AND citation_ok, i.e. "the *cited* passage supports the answer"); end-to-end judges vs `acceptable`.
95% CIs are cluster bootstrap (clusters = base question).

### 4.2 The judges

| name | model | what it is |
|---|---|---|
| `faith_v0`, `correct_v0`, `overall_v0` | Gemma, Qwen | **before**: naive one-shot prompts ("Is every statement supported? YES/NO", "Is the answer correct? YES/NO", one JSON with 5 flags) |
| `faith_v1` | Qwen | rubric + step-by-step supporting quotes (chain of thought) |
| `faith_v2` | Qwen | Ragas-style: LLM extracts atomic claims, LLM verifies each (our prompts) |
| `faith_v3` | Gemma, Qwen | **after**: the same verification, but claims = a deterministic sentence split (added after seeing on **dev** that v2's LLM extractor silently dropped an appended hallucination) |
| `correct_v1` | Gemma, Qwen | reference-guided rubric: digit scripts equal, 1-digit differences are errors, all parts of a multi-fact reference required, abstention rules; brief CoT |
| `cite_v1` | Gemma, Qwen | does the CITED passage alone state the answer's content? (quote then verdict) |
| `overall_pipeline_v3` | Gemma, Qwen | **after, end-to-end**: `faith_v3` AND `correct_v1` AND `cite_v1` AND deterministic checks (answer script == question language; abstains iff the question is unanswerable) |
| `overall_pipeline` | Qwen | same with `faith_v2` |
| `string_match` | - | non-LLM baseline for correctness: reference string (digit/Arabic-normalised, whole-number aware) occurs in the answer |
| Ragas faithfulness (==1.0) and FactualCorrectness (threshold tuned on dev) | Qwen as Ragas evaluator on 96 stratified items (8 per type) | the off-the-shelf metrics, thresholded into pass/fail |

Gemma throughput under shared load fell to 3-5 calls/min, so the schedule was trimmed (documented in `scripts/rageval/03_planted_set_and_judges.sh`): Gemma ran the v0 baselines on all
items and the expensive judges (`correct_v1`, `cite_v1`, `faith_v3`, pipeline) on the **test split only**; the LLM-decomposition variants (`faith_v1`, `faith_v2`, `overall_pipeline`)
ran on Qwen only (Qwen was run on everything). Ragas on the planted set was run with Qwen3-4B as the evaluator (96 items, 8 per type; the Gemma evaluator was used on the real RAG answers, section 3, because Gemma throughput did not allow both).

**Takeaways.**
1. **Prompt/rubric design matters enormously for a small judge and little for a strong one - on this set.** Qwen3-4B's one-shot end-to-end judge has kappa 0.42; the decomposed pipeline reaches 0.97. Gemma's one-shot judge is already at 0.95 and the pipeline adds +0.05 (CI touches 0).
   The improvement is significant for Qwen (CI far from 0) and for the Gemma correctness / faithfulness components (+0.13, +0.19) but only marginal for Gemma end-to-end.
2. **A planted-error set of this kind saturates.** Gemma's `correct_v1`, `faith_v3` and the pipeline score kappa = 1.00 [1.00, 1.00] on 91 items: the set can no longer rank good judges. A perfect score on easy planted errors says "this judge is not broken", not "this judge is excellent" - the discriminating power lives in harder cases (section 8).
3. **Much of the end-to-end gain is not LLM cleverness.** The ablation (4.6) shows the two deterministic checks (language script, abstain-iff-unanswerable) are what close the last gap for every pipeline; LLM parts alone reach recall 0.89-0.95. Use code wherever the property is mechanical.
4. **Where weak judges fail (flag rates by type, ALL items; ideal: ~1.00 for defects, ~0.00 for clean/ok):**
   * Qwen one-shot `overall_v0` flags only **11%** of appended hallucinations, **0%** of omitted facts, **0%** of wrong-language answers, **19%** of wrong citations and **0%** of wrong abstentions - it catches almost only swapped numbers/entities. Gemma's one-shot `overall_v0` is better but still misses 17% of hallucinated additions, 36% of wrong-language answers and 38% of wrong citations.
   * Claim *extraction* is a hidden failure point: `faith_v2` (LLM decomposes, then verifies) flags only 33% of appended hallucinations (the extractor omits the invented sentence), while the *same verifier* fed a deterministic sentence split (`faith_v3`) flags 100%. The Ragas faithfulness recipe has this structure.
   * `faith_v1` (single CoT with quotes) is as good as `faith_v3` on faithfulness (kappa 0.95 vs 0.93) at the same cost - decomposition is not automatically better than a good rubric.
   * `string_match` is a strong correctness baseline *on this set* (kappa 0.96) precisely because base answers were selected to contain the reference string. It has no way to see appended hallucinations (0%), wrong citations (0%), and mis-flags 50% of wrong-language answers (entity names differ across languages). It fails in production wherever answers paraphrase or switch language (e.g. real example from the baseline: reference `711.988`, answer `711,988`).
5. **Numbers and Arabic digits (the question you asked): not a blind spot for competent judges here.** Every Gemma judge and Qwen's CoT judges flag 100% of wrong numbers including x10 errors and off-by-one-year ("near") errors, in both ASCII and Arabic-Indic digits, with 0% false positives on correctly re-scripted numbers. The weak naive judges leak: Gemma `correct_v0` misses 27% of near-miss numbers; Qwen `correct_v0` and `faith_v0` and Ragas faithfulness produce false positives on correct Arabic-Indic / separator variants (12%, 12%; Ragas faithfulness 17% on test, 38% over all 8 scored numeral variants).
   *Caveat:* only 12+18 wrong-number items and 10 numeral variants, and one digit script pair; this is not evidence that no variant (number words, `1.5 مليون`, units, Eastern/Western separators such as `711.988` vs `711,988`) is missed.
6. **Per language:** with good prompts there is no Arabic penalty (Gemma kappa 1.00 en / 1.00 ar for `correct_v1`); weak prompts are noticeably worse in Arabic for faithfulness (Qwen `faith_v0` FPR 0.42 ar vs 0.13 en, Gemma `faith_v0` kappa 0.74 ar vs 0.90 en). Cross-lingual (question language != evidence language) items are not harder for the good judges.

gemma: self-preference suite used 19 pairs; Qwen-written / Gemma-written length ratio = 0.94.

qwen: self-preference suite used 40 pairs; Qwen-written / Gemma-written length ratio = 0.94.

*Small n: 8 base pairs per suite for Gemma (16 verdicts), 24 for Qwen (48 verdicts); the self-preference suite has 19 (Gemma) and 40 (Qwen) pairs. Intervals are Wilson on verdicts and are optimistic because the two orders of a pair are not independent.*

* **Position bias (Qwen3-4B): severe when answers tie, absent when they differ.** Given two equally correct answers (short vs the same answer plus a content-free sentence) Qwen picked slot A **92%** of the time and flipped its decision under swap in 83% of pairs (order-consistent 17%). Given a correct and a wrong answer it picked the correct one 98% of the time with consistent verdicts (96%). So position bias lives exactly where a pairwise judge is most needed - close calls. Gemma showed none (slot A 50%, order-consistent 100% in every suite).
* **Verbosity: no "longer wins" effect, but padding can rescue a wrong answer for the small judge.** Qwen picked the wrong-number answer when it was padded with fluff in 8% of verdicts vs 2% unpadded (n=48; difference within noise). Gemma preferred the *concise* answer 100% of the time (the prompt says "if both agree, prefer the clearer one"), i.e. the opposite of verbosity bias - a prompt-induced preference, still a bias.
* **Digit-script preference:** with a reference in ASCII digits, both judges prefer the ASCII-digit version of an otherwise identical correct answer (Gemma 100%, Qwen 90%), though pointwise correctness judges treat them as equal (section 4.7). A pairwise judge is *not* script-invariant - normalise digits before comparing, or avoid pairwise grading for numeric answers.
* **Self-preference: not detectable, and confounded.** Both judges preferred the *Qwen-written* answer (Gemma judge picks the Gemma-written answer 39% of the time, Qwen judge 35%). A model that favoured its own text would split the other way for the two judges; this points to a style effect shared by both (Qwen answers were 6% shorter), not self-preference. 19-40 pairs: do not over-read.
* **Language bias:** quantified in 4.8 (per language and cross-lingual): weak prompts are worse on Arabic faithfulness (Qwen `faith_v0` false-positive rate 42% on Arabic vs 13% on English items), calibrated judges are not.

## 6. Using the evaluation to improve the RAG system (measured before / after)

**What the eval showed (section 2)**: (a) the gold passage is missing from the top-3 for 19% of answerable questions, and 28 of the baseline's 34 refusals follow from that; (b) 27% of real answers are in the wrong language.
**Changes made (config I):** retrieve 10 dense candidates and rerank with the cross-encoder to the top 3 (fixes a), and add one explicit output-language instruction to the prompt (fixes b; prompt v3 = v1 + "write your answer in English/Arabic ... even when the documents are in another language").
**Hypotheses that were written down before the end-to-end run:** primary metric = *acceptable-answer rate* (correct by the calibrated judge AND in the question's language AND, for unanswerable questions, abstains); secondary = retrieval hit@3, over-refusal, wrong-language rate.
**What was tried (honest accounting).** Retrieval-only (no LLM): 8 retrieval configurations on the same 160 questions (2.1); end-to-end with Gemma: only A and I. The reranker and the language fix were chosen *after* looking at these same 180 questions, so the in-sample comparison is optimistic; we therefore also ran A and I **unchanged on 48 fresh questions** that were used for nothing else (`heldout_ab.py`; 24 en / 24 ar; the baseline retrieved the gold passage for 38 of 48).
**Judges:** correctness = Gemma `correct_v1` (test-split kappa 1.00, chosen *because* it was the best-calibrated); attribution = Qwen `cite_v1` (100% pass for both systems, so it cannot discriminate - listed for completeness); language and abstention are deterministic.

Column legend: *acceptable* = judged correct AND answered in the question's language (and, for unanswerable questions, abstained); *success* = judged correct by `correct_v1` (language ignored; refusals on answerable questions count as failures, correct refusals on unanswerable ones as successes); *success_str* = the reference string occurs in the answer (non-LLM, language-sensitive); *grounded* = cited passage supports the answer (`cite_v1`); *gold_hit* = gold passage in the retrieved top-3; *over-refusal* = answerable question refused; *unans. abstain* = unanswerable question refused; *right-language* = share of non-refused answers written in the question's language.

### 6.3 Reading the numbers

* **The headline improvement is large and real**: acceptable-answer rate **59.4% -> 85.0%** in-sample (+25.6 points, 95% CI [+18.3, +32.8]; McNemar 51 questions fixed vs 5 broken) and **58.3% -> 85.4%** on fresh questions (+27.1 [+14.6, +39.6]; 13 fixed, 0 broken). The two estimates agree within their intervals, so the in-sample optimism is small *for this effect*.
* **Most of it is the cheap deterministic fix, not retrieval.** The language instruction lifted right-language answers from 73% to 100% (+26.8 points; 33 questions fixed, 0 broken) - essentially the whole gain in the end-to-end metric. Reranking lifted gold-hit@3 by 10.6 points [+5.0, +16.2] and cut over-refusal from 21.2% to 11.2% (-10.0 [-15.6, -5.0]).
* **Pure content correctness improved only modestly and is borderline.** Among all 180 questions, "judged correct" went 78.3% -> 85.0% (+6.7 [+1.1, +12.2], bootstrap p = 0.020, McNemar p = 0.029). With 7 paired metrics examined, a Bonferroni threshold would be 0.007, so this one would **not** survive correction. On the 48 fresh questions the same metric moved +6.2 points [0.0, +14.6] (McNemar p = 0.25) - same direction and size, but the test cannot resolve it: the minimum detectable paired difference at n = 48 is ~18 points, at n = 180 ~10 points.
* **The unanswerable questions did not improve because they cannot**: 20/20 abstentions before and after (Wilson lower bound ~84%; 0 headroom). The strict-grounding prompt we had planned was therefore never run.
* **Judge-dependence check.** With the cheaper Qwen3-4B `correct_v1` as the correctness judge the numbers shift but the conclusion does not: acceptable 55.0% -> 78.9% (+23.9 [+16.7, +31.1]); content success +6.7 [+0.6, +12.8]. Qwen is the stricter judge on real answers: across all 268 real answers the two judges agree on 91.0% (kappa 0.48); in 23 of the 24 disagreements Gemma says correct and Qwen says incorrect, and in the 5 we read by hand (reference `ثلاثة`, answer "...ثلاثة أنواع أخرى مشكوك فيها", etc.) Gemma was right - Qwen penalised harmless extra detail that its own rubric allows, and once misread the reference (claimed it said "18th century" when it said "19th"). The two judges agree at kappa 0.85 on planted items but only 0.48 on real answers: **the planted set overstated how interchangeable they are on real outputs** - exactly the gap the human-label hook is meant to measure.
* **What would change the conclusion**: a judge with a systematic bias against wrong-language answers (Gemma's `correct_v1` ignores language by design, the deterministic check owns it); a different corpus where the generator already answers in the right language; or true retrieval differences at larger scale (the latency cost of reranking 10 candidates with a CPU cross-encoder was not measured).

## 7. Human-label hook (for you to fill; we did not label anything)

`runs/rageval/human_labeling.csv` (written by `export_human.py`; not committed because it quotes XQuAD paragraphs) - 40 rows, shuffled, **label columns blank**: 20 real baseline answers (4 each of en->en, en->ar-passage, ar->ar, ar->en-passage, plus 4 unanswerable) and 20 planted items
(1-2 of each error type; the sheet does not say which rows are planted). Columns: question, question language, reference answer, up to three retrieved documents, the system answer, then
`human_faithful`, `human_correct`, `human_acceptable` (1/0) and `human_notes`. Instructions: [HUMAN_LABELING.md](HUMAN_LABELING.md).
`runs/rageval/human_labeling_key.json` holds the planted truth and every judge's verdict per row - **do not open it until you have labelled**.

```bash
python -m arretrieval.rageval.agreement            # after filling the CSV (partial files work)
```

`agreement.py` prints, per judge and per axis: n, raw agreement, Cohen's kappa, and the confusion matrix (rows = human [bad, good], columns = judge [bad, good]), separately for all rows / real-only / planted-only;
your agreement with the planted ground truth (a check on your own labelling and on rubric ambiguity); and a list of rows where you and the best end-to-end judge disagree. It was tested end-to-end on a synthetic
label file in `/tmp` (ground truth + 10% noise); the real CSV is untouched.

What to expect (hypotheses to test, not results): on the 20 planted rows your kappa with the judges should be close to the planted-set numbers above; on the 20 real rows it will be lower and noisier (n = 20 gives a kappa interval of roughly +-0.3) -
the real-row disagreements are the interesting ones.

## 8. What broke, what we corrected, and what is still imperfect (negative results included)

**Environment / tooling**
* **Ragas 0.4.3 does not import with the current langchain stack.** `pip install ragas` pulled `langchain-community 0.4.2`, which removed `chat_models.vertexai`; `import ragas` fails with `ModuleNotFoundError`. Fix: pin the langchain 0.3 line (`langchain<1 langchain-core<1 langchain-community<0.4 langchain-openai<1`; see `requirements/rageval.lock.txt`).
* **Ragas 0.4 changed API.** The classic `ragas.metrics.Faithfulness` objects are gone; metrics live in `ragas.metrics.collections` and take an *Instructor-style* LLM (`agenerate(prompt, PydanticModel)`). `llm_factory(...)` needs an OpenAI client and gives no hook for the cross-process concurrency cap, `enable_thinking=false` or a persistent cache, so `ragas_adapters.py` implements the 2-method `InstructorBaseRagasLLM` interface on top of llama.cpp's grammar-constrained `response_format=json_schema`. Ragas' own prompts and claim/NLI logic are unchanged. 0 structured-output parse failures in ~1,150 Qwen-evaluator calls (see 3).
* **The embed/rerank service went away mid-run** (found scaled to 0 -> 503; not our action). `retrieval.py` fell back to in-process copies of the same two models (vectors verified identical to the stored ones). Everything in this report after ~21:12 used the in-process path (CPU, 6 threads), which is the only path this repository ships.
* **The machine became unreachable over SSH for ~13 minutes at ~23:40** (load average 590-720 from other tenants' processes). Our jobs survived because every long job is a detached script with an on-disk LLM cache.
* **Gemma throughput was the binding constraint** (3-20 calls/min, 4 slots shared with other tenants, decode ~10 tok/s/slot). We cut scope accordingly and say so wherever it matters: Gemma CoT judges ran on the test split only; Ragas on the RAG answers ran on a stratified 20-question subset (16 answerable + 4 unanswerable); Ragas on the planted set used the Qwen evaluator only; Gemma bias checks use n = 8 pairs per suite.

**Measurement bugs we caught (and why they matter)**
* `parse_json` returned the *inner dict* for a one-element JSON list, so `faith_v2` reported "unparsable" for exactly the one-claim answers. Found by a 6-item hand smoke test; regression test added (`tests/rageval/test_llm_parse.py`).
* The first planted set was **70% Arabic** because 30% of English-question base answers were dropped for answering in Arabic (the same defect as in section 2.2). We regenerated base answers with the explicit-language prompt where needed and interleaved languages; the first set was archived and is not part of this repository.
* Entity swaps were initially absurd (an actress replaced by `DTIME(f(n))`, a complexity class), making the defect trivially detectable; swaps now prefer entities from the same Wikipedia article with matching word count. Remaining swaps are sometimes type-implausible in Arabic (a *colony* replaced by a person's name), so entity-swap recall is still an upper bound.
* **Label hygiene (found by looking at why good judges "missed" omitted facts):** 3 of the first 14 "omitted fact" items were not omissions (the short answer already contained the second fact, or both questions had the same answer), and the substring matcher accepted `5` inside `565`. We made reference matching whole-number-aware, re-verified every item that must contain its reference, and **excluded 6 items** (flagged in `meta_items.jsonl`, ids kept stable, ignored by all analyses). Lesson: a "judge error" is sometimes a label error - always read the disagreements.
* Ragas FactualCorrectness with the bare XQuAD span as reference: toy check 0.0 for a correct answer (`toy_ragas.py`, `fc_short_ref`). All reference-based Ragas numbers use the sentence containing the span.

**Hypotheses that did not pan out**
* *"Chunking the passages fixes embedder truncation"*: chunked dense top-3 hit 0.831 vs 0.812 (inside the CIs). Not adopted.
* *"A stricter 'only answer if explicitly stated' prompt reduces hallucination"*: the baseline already abstained on 20/20 unanswerable questions, so there was nothing to fix and a stricter prompt could only raise over-refusal. Not run.
* *"Decomposing claims (Ragas-style) beats a plain rubric CoT"*: it did not (`faith_v2` kappa 0.68 vs `faith_v1` 0.95 on test, Qwen), because the extractor drops claims.

**Still imperfect**
* The planted set saturates for strong judges (kappa 1.00); it cannot separate them. Harder planted cases (paraphrased unsupported inferences, partial numeric agreement, ambiguous references) are the next step.
* Planted errors are synthetic; judge kappa against them is an upper bound on kappa against real errors. The human labelling hook (section 7) is how to measure that.
* Test-split per-type counts are small (4-15); intervals for individual error types are wide.
* Ragas on the planted set was run with Qwen3-4B as evaluator (96 items), not Gemma; the FactualCorrectness threshold for FactualCorrectness was tuned on dev items only (tau = 0.10 for all three modes - i.e. the metric separates only the extreme scores).
